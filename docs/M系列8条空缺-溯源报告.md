## 一、证据链

### 证据 1：文件本身是模板批量生成的空壳

`M14_.md` 的完整字节（`od -c`）：

```
#   M   1   4      \n  \n   -   分类：M 动态风格 · 其他特别的风格 \n \n   ## 风格提示词 \n \n \n
```

即：

```markdown
# M14 

- 分类：M 动态风格 · 其他特别的风格

## 风格提示词

```

8 个文件除编号外**字节数完全相同（都是 81）**，结构完全相同。

文件名规律是 `{编号}_{名字}.md`。这 8 个文件下划线后面**直接就是 `.md`**，说明生成器在写文件名时 `名字` 这个变量就已经是空字符串——不是"先有名字、后来内容被删"，而是**从头到尾没有名字**。

### 证据 2：UP 主自己的挑选网页里，这 8 条连 `prompt` 字段都不存在

`风格挑选.html` 内嵌了 341 条 JSON 数据（`<script id="data">`）。全库字段分布：

| `fit` | 291 |

| **`prompt`** | **141** |
| `tags` | 124 |
| `prompt_en` `year` | 98 |
| `desc_en` | 90 |

这 8 条在 JSON 里的完整记录（以 M14 为例，其余 7 条同构）：

```json
{ "id": "M14", "s": "M", "cat": "其他特别的风格", "name": "", "img": "",
  "file": "风格提示词/M_动态风格/M14_.md" }
```

只有 6 个 key，**没有 `prompt`、没有 `desc`、没有 `fit`**。而库里另有 141 条带 `prompt`（长度 27–2825 字符），其中包含 M1、M2、M18、M19。

对照：全库 341 条中 `name` 为空的**恰好只有这 8 条**，无其他条目。

### 证据 6：编号与生成方式的旁证

M 系列 40 条中 31 条在正文里带 `prompt-motion.com` 参考链接，不带的恰好是这 8 条加 M1（M1 已被重写为详细版）。文件名模板是 `M{编号}_{标题}.md`，而 81 字节**正好等于 `{标题}` 为空字符串时该模板的渲染结果**——若是"发放时丢了正文"，文件名里应当残留真实标题，而不会连标题一起消失。

## 二、唯一一条指向"曾经有内容"的线索（及其限度）

`风格提示词/R_照参考学来的/R5_像素赛博 · 复古游戏.md` 第 16–18 行：

```markdown
### 相近的旧编号

M14、L49、L50、X24
```

这是全库 8 条里**唯一**被其他文件引用到的一次（M15/M16/M17/M26/M35/M39/M40 被引用 0 次）。

该字段确实引用真实条目：同段落里 L49（16-bit 像素 RPG，11555 字节）、L50（HD-2D，12606 字节）、X24（RPG 任务，4613 字节）都有完整内容，且主题都是像素/复古游戏；R6 也引用了 M30（东方意境，590 字节，有内容）。

**能推出什么**：UP 主写 R5 时，"M14"这个编号在他心里对应一个像素赛博/复古游戏方向的风格。

**不能推出什么**：不能推出 `M14_.md` 里曾有正文。最合理的解释是——这个风格最终**以 R5 的形式发布了**（R5 的"定死的画法"写得非常具体：480×270 小画布、28 色调色板、拜耳抖动、放大 4 倍不做平滑），M 系列的槽位因此留空，而 R5 的"相近的旧编号"保留了这段历史痕迹。

但这只是**推测，无一手来源可证实**。R5 的正文署在 R5 名下，把它复制进 `M14_.md` 并声称"这是 M14 原本的内容"属于伪造。

## 五、据此已落实的修正

`README.md` 原先写「如果你知道这 8 条原本该是什么，欢迎在 issue 里补充」，措辞偏开放，容易让人误以为是搬运丢失。现已改为：**原件即空、非搬运丢失，并经第三方独立镜像逐 blob 校验**；同时说明本仓库没有用他人内容冒充原作填进去，若手上有更新版原包可开 issue 提供。

`风格提示词/README.md` 索引里这 8 行的批注也从「正文为空，原样保留」改为「原件即空：无名字、无正文」，该节说明同步更新。索引由脚本生成，改动落在生成器上，产物与生成器保持一致。

这 8 个 `.md` 文件本身**一个字节都没有改**（仍是 81 字节），全库 556 个原文件与搬运前快照逐字节一致的结论依然成立。
